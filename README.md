# RenderPR: Core Agents & System Architecture

## Overview
GitHub bot that VISUALLY reviews frontend Pull Requests changes. It dynamically provisions ephemeral infrastructure, captures UI screenshots across different viewports, and uses a LLM to analyze frontend regressions alongside the code diff. It is deployed strictly into the user's own cloud environment (BYOC = zero trust).

Following the initial review, the bot shifts into a conversational state. It remains active for a predefined idle window (e.g., 15 minutes), polling the PR thread for developer follow-up questions. Developers can request real-time modifications—such as rendering specific viewports, toggling dark mode, or testing accessibility contrast—allowing the bot to re-render the application and analyze the output on the fly.

## 1. Component Architecture & Tech Stack

### 1.1 Webhook Router (Inbound Event Orchestrator)
* **Technology:** AWS API Gateway + AWS Lambda (Python 3.12)
* **Purpose:** Listens for inbound event payloads from the GitHub App (e.g., Pull Request opened, or a new comment matching `@renderpr`). It validates the request signatures, extracts the branch metadata, and executes an asynchronous trigger to launch the core execution task before immediately returning a `200 OK` to GitHub to avoid timeouts.

### 1.2 Interactive Execution Sandbox (Ephemeral Host)
* **Technology:** AWS Fargate (ECS Serverless Container running a Python 3.12 & Node base image)
* **Purpose:** Serves as the stateful, isolated workspace where the targeted repository branch is cloned. It executes the Next.js dependency installation, spins up the local development web server, and hosts the continuous interactive execution lifecycle loop.

### 1.3 Visual Automation Agent (The Eyes)
* **Technology:** Playwright (Python bindings)
* **Purpose:** Programmatically navigates the headless browser instance to the local web server address. It dynamically resizes viewports to evaluate responsiveness, modifies media queries to test dark mode parameters, captures high-resolution screenshot buffers of the interface, and gathers console log errors.

### 1.4 Conversation Polling Agent (The Listener)
* **Technology:** GitHub REST API Client (Python standard library / HTTPX)
* **Purpose:** Runs a continuous `while` loop within the running Fargate container to track the specific Pull Request timeline. Every 10 seconds, it parses new thread comments for the `@renderpr` keyword trigger, extracting natural-language commands to pass down to the visual automation engine.

### 1.5 Multimodal Review Agent (The Brain)
* **Technology:** OpenAI API (GPT-4o) / Anthropic API (Claude 3.5 Sonnet) / OpenRouter
* **Purpose:** Synthesizes the raw code diff pulled from Git alongside the binary screenshot images generated by Playwright. It runs contextual layout, usability, and WCAG accessibility evaluations to output structured markdown critiques.

### 1.6 Infrastructure-as-Code Configuration (The Installer)
* **Technology:** AWS Cloud Development Kit (CDK v2 using TypeScript)
* **Purpose:** Packages the entire cloud topology (IAM policies, VPC subnets, Lambda entry points, API Gateways, and ECS definitions) into a single, deployable codebase that users can securely stand up inside their own AWS cloud accounts via their local terminals.

## 2. Frontend Data Mocking & Network Interception Strategy

To ensure high-speed compilation, zero external database dependencies, and complete isolation, RenderPR executes the frontend application exclusively without spinning up a live backend stack. The network layer is dynamically stubbed at runtime.

### 2.1 Data Interception Protocol
* **Technology:** Playwright Router API (`page.route()`) / Mock Service Worker (MSW)
* **Purpose:** Intercepts all outgoing asynchronous HTTP/HTTPS network traffic generated by the Next.js client component routes matching specific API patterns (e.g., `/api/v1/*` or external microservice endpoints). 

### 2.2 Operational Mechanics
* **Fixture Resolution:** When the Visual Automation Agent initiates a page render, the network router catches API requests before they leave the headless browser sandbox. It maps the requested endpoint to a local static JSON file (`*.json`) located within the repository's `.renderpr/fixtures/` directory.
* **State Simulation:** Returns deterministic HTTP status codes (e.g., `200 OK`, `421 Unprocessable Entity`, `500 Server Error`) along with the pre-baked JSON payload to the frontend. This allows the Multimodal Review Agent to evaluate how components behave across diverse states (e.g., empty states, loading skeletons, error boundaries, or populated dashboards) without requiring a live runtime API layer or test database seeding.

## 3. Agent Execution Sequences & Event Lifecycles

This section details how sequential data transitions through different runtime boundaries, shifting from asynchronous serverless triggers to a synchronous long-polling loop inside the container workspace.

### Core Pipeline Execution Flow

```text
[GitHub App Event]
       │
       ▼ (Webhook JSON Payload)
[AWS API Gateway] 
       │
       ▼ (Proxies Event)
[AWS Lambda (Router)] ────(Signs & Validates Payload)
       │
       ▼ (Invokes via ECS RunTask API)
[AWS Fargate Task] ◄────────────────────────────────────────┐
       │                                                    │
       ├─► [1. Workspace Provisioner]                       │
       │     └─► Clones PR Branch & Installs Dependencies   │
       │                                                    │
       ├─► [2. Visual Automation Engine]                    │ (Continuous Polling Loop
       │     └─► Launches Headless Playwright Browser       │  until Idle Timeout)
       │     └─► Boots Next.js Dev Server (Port 3000)       │
       │                                                    │
       ├─► [3. Multimodal Inference Engine]                 │
       │     └─► Extracts Git Diff vs Screenshot Buffers    │
       │     └─► Dispatches Context Payload to LLM API      │
       │     └─► Posts Structured Markdown PR Comment       │
       │                                                    │
       └─► [4. Conversation Polling Agent] ─────────────────┘
             └─► Polls GitHub Thread every 10 seconds
             └─► Detects @renderpr commands -> Triggers Phase 2
```

## 4. State Boundaries & Security Contexts

Because RenderPR is built as a Bring-Your-Own-Cloud (BYOC) infrastructure model, strict isolation of state and authentication variables must be maintained across runtime boundaries.

| Component / Layer | State Type | Lifespan | Access Scope / Permissions |
| :--- | :--- | :--- | :--- |
| **Inbound Webhook (Lambda)** | Stateless | Ephemeral (Single Request) | Read-only access to verify GitHub HMAC signatures. Minimal IAM permissions. |
| **Workspace Sandbox (Fargate)** | State-Isolated | Persistent for active session max 15 mins | Local filesystem container access. Read/Write to local node_modules and Git working directories. |
| **Browser Context (Playwright)** | Ephemeral | Refreshed per command instruction | Isolated cookie jar and local storage per render target to prevent data cross-contamination. |
| **LLM Orchestration Layer** | Stateless | In-Memory (Cleared on loop tick) | Pulls keys from Fargate Environment variables via secure runtime injection. |

## 5. Agent Failure Modes & Self-Healing Policies

Autonomous loops running inside containers are susceptible to hanging builds, API rate limits, and broken dependencies. RenderPR implements the following defensive resilience guards:

### 5.1 Next.js Local Server Compilation Failures
*   **Failure Scenario:** The developer introduces a syntax or TypeScript compilation error that crashes `npm run dev` or `npm run build` during initialization.
*   **Mitigation Strategy:** The Workspace Provisioner monitors standard error streams (stderr). If compilation drops with a non-zero exit code, the bot bypasses Playwright execution entirely, captures the raw compilation log, posts it as a diagnostic failure markdown comment on the PR, and gracefully runs an exit sequence.

### 5.2 LLM API Ingestion Rate-Limiting (429 Tokens)
*   **Failure Scenario:** High-volume text diffs mixed with multiple screenshot uploads exceed the immediate token-per-minute (TPM) allocation bounds of the target model.
*   **Mitigation Strategy:** The Multimodal Review Agent implements an exponential backoff retry mechanism with jitter. If an API request encounters an HTTP 429 error, it retries up to three times over a 30-second window before appending a "Review Paused: LLM Rate Limit Hit" status notification directly into the PR commit check status.

### 5.3 GitHub Thread Polling Expiry (The Zombie Kill-Switch)
*   **Failure Scenario:** A developer invokes the bot, but walks away or drops the interaction loop without typing any closing instructions.
*   **Mitigation Strategy:** The Conversation Polling Agent keeps a persistent internal Unix timestamp marker tracking the last observed user interaction. If `current_time - last_interaction_time > 900_seconds`, the Fargate script posts a closing summary notification and self-destructs the container environment immediately to eliminate lingering compute overhead.
